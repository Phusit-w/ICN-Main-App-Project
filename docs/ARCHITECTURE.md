# โครงสร้างของเว็บแอป

## จุดสำคัญที่ต้องเข้าใจก่อน: ไม่มี "frontend server" กับ "backend server" แยกกัน

แอปนี้ใช้ **Next.js** ซึ่งเป็น full-stack framework — frontend กับ backend รันอยู่ใน **โปรเซสเดียวกัน เครื่องเดียวกัน** ไม่ใช่สถาปัตยกรรมแบบ 2 เซิร์ฟเวอร์แยกกันคุยกันผ่าน API (เช่น React แยก + Express/Django แยก) ที่หลายคนคุ้นเคย

## Frontend

- **Next.js 16 (App Router)** + React 19 + TypeScript
- แบ่งเป็น 2 แบบ:
  - **Server Components** (ค่าเริ่มต้น) — render เป็น HTML ที่ฝั่งเซิร์ฟเวอร์ก่อนส่งมา เช่น `app/page.tsx` (หน้า History) ดึงข้อมูลจาก DB ตรงๆ ในนี้เลย
  - **Client Components** (`"use client"`) — โต้ตอบได้ในเบราว์เซอร์ (กรอกฟอร์ม, กดปุ่ม) เช่น `BillEditor.tsx`, `EntryFormFA017.tsx`
- ไม่มี CSS framework แยก — สไตล์เขียนแบบ inline `style={{...}}` ตรงจาก design source

## Backend

- **ไม่มี REST API / GraphQL แยกต่างหาก** — ใช้ **Server Actions** แทน (ไฟล์ใน `actions/*.ts` ที่มี `"use server"` บรรทัดแรก) เป็นฟังก์ชันที่รันบนเซิร์ฟเวอร์เท่านั้น แต่เรียกจาก component ฝั่ง frontend ได้ตรงๆ เหมือนเรียกฟังก์ชันธรรมดา (เช่น `BillEditor.tsx` เรียก `saveRecord()` จาก `actions/records.ts` ได้เลย ไม่ต้อง fetch("/api/...") เอง) — Next.js จัดการส่งข้อมูลไป-กลับให้อัตโนมัติ
  ข้อยกเว้น: route handler ใต้ `app/api/` สำหรับไฟล์อัปโหลด/ดาวน์โหลด และสำหรับโปรแกรมภายนอกที่ไม่มี session cookie
  (crawler ของ Project Card, SOC Runner ใต้ `/api/soc-runner/` ซึ่งยืนยันตัวด้วย bearer token — ดู `docs/SOC-RUNNER.md`)
- **Middleware** (`proxy.ts`) — โค้ดที่ดักทุก request ก่อนถึงหน้าไหนก็ตาม ตรวจ session cookie ของระบบ login รายคน (`lib/auth.ts`) + rate limiting ที่นี่จุดเดียว ไม่ผ่าน → redirect ไป `/login`

## Database

- **PostgreSQL** เข้าถึงผ่าน **Prisma ORM 7** (`prisma/schema.prisma` = นิยามตาราง, `lib/prisma.ts` = ตัวเชื่อมต่อจริง)
- ตาราง: `ExpenseRecord` (บิลจริง), `SavedEmployee`/`SavedItem` (บันทึกไว้ใช้ซ้ำ), `User` (บัญชี login รายคน), `EmployeeProfile` (เลิกใช้แล้ว แต่ยังอยู่ในตาราง)

## ตอนนี้ทุกอย่างเชื่อมกันผ่านอะไร (สถานะปัจจุบัน)

```
เบราว์เซอร์ (คุณ/เพื่อนร่วมงาน)
   │  (ผ่าน ngrok tunnel หรือ LAN IP ตรงๆ)
   ▼
เครื่อง Windows นี้เครื่องเดียว (OI66-0318)
   ├─ Next.js server (npm run start, พอร์ต 3000)   ← frontend + backend อยู่ตรงนี้ทั้งคู่
   │      │
   │      ▼ (Prisma)
   └─ PostgreSQL ชั่วคราว (npx prisma dev, พอร์ต 51218)   ← database อยู่ตรงนี้
```

**ทุกอย่างอยู่บนแล็ปท็อปเครื่องนี้เครื่องเดียว** ไม่มีอะไรอยู่บนเซิร์ฟเวอร์บริษัทเลยตอนนี้ — `ngrok`/LAN IP เป็นแค่ "ท่อ" ที่พาคนนอกมาถึงเครื่องนี้ ไม่ใช่โครงสร้างของแอปเอง และฐานข้อมูลที่ใช้อยู่เป็นตัว**ชั่วคราวสำหรับ dev เท่านั้น** (ปิด terminal เมื่อไหร่ก็เสี่ยงข้อมูลหาย — ดู `docs/PROJECT-OVERVIEW.md` ข้อ 1)

## ถ้าจะย้ายไปเชื่อมกับเซิร์ฟเวอร์บริษัทจริง ต้องทำอะไรบ้าง

หลักการคือย้าย **ทั้ง 3 ส่วน (frontend+backend+database) ไปรันบนเซิร์ฟเวอร์แทนแล็ปท็อปเครื่องนี้** — มี 2 วิธีให้เลือกตามสเปกเซิร์ฟเวอร์ (เอกสารเตรียมไว้ครบแล้วทั้งคู่):

| | เซิร์ฟเวอร์รองรับ Docker/virtualization | เซิร์ฟเวอร์ไม่รองรับ (VT-x/AMD-V ปิดใน BIOS) |
|---|---|---|
| เอกสาร | `docs/DEPLOY.md` | `docs/DEPLOY-WINDOWS.md` |
| Database | Postgres รันใน container | ติดตั้ง PostgreSQL ตรงบน Windows Server |
| App | รันใน container | รันด้วย Node.js ตรงๆ ผ่านสคริปต์ใน `deploy/windows/` |
| HTTPS | มีให้ในตัว (Caddy) | ไม่มีในตัว ต้องจัดการเอง |
| Backup อัตโนมัติ | มีให้ในตัว | ไม่มีในตัว ต้องจัดการเอง |

**ขั้นตอนคร่าวๆ ไม่ว่าจะเลือกทางไหน:**

1. **ยืนยันเซิร์ฟเวอร์กับ IT** — ก่อนหน้านี้สงสัยว่า `192.168.99.1` น่าจะใช่ (เดาจากพอร์ตที่เปิด) แต่ยังไม่ได้ยืนยันจริงกับ IT ว่าใช้เครื่องนี้ได้ไหม รวมถึงเช็คว่ารองรับ virtualization หรือเปล่า (จะได้เลือกตารางด้านบนถูก)
2. **ขอสิทธิ์เข้าเซิร์ฟเวอร์** (RDP หรือช่องทางที่ IT ให้)
3. **คัดลอกโปรเจกต์ทั้งโฟลเดอร์** ไปที่เซิร์ฟเวอร์
4. **ตั้งค่า `.env` ใหม่บนเซิร์ฟเวอร์** — รหัสผ่าน DB และ `SESSION_SECRET` ต้องเป็นค่าจริงที่ปลอดภัย **ไม่ใช่ค่าที่ใช้อยู่ตอนนี้บนแล็ปท็อป** แล้วเพิ่มบัญชีผู้ใช้จริงผ่าน Prisma Studio (ดูหัวข้อ "การเพิ่มผู้ใช้" ใน `docs/DEPLOY.md`/`docs/DEPLOY-WINDOWS.md`)
5. **รันตามขั้นตอนในเอกสารที่เลือก** (`docker compose up -d --build` หรือสคริปต์ native Windows)
6. **ย้ายข้อมูลเก่า (ถ้ามีข้อมูลจริงที่อยากเก็บจากช่วง pilot)** — ข้อมูลใน DB ชั่วคราวบนแล็ปท็อปตอนนี้**ไม่ย้ายไปเองอัตโนมัติ** ต้อง export/import ด้วยมือ (`pg_dump` จากเครื่องนี้ → `psql`/`pg_restore` เข้าเซิร์ฟเวอร์ใหม่) ถ้าไม่ต้องการข้อมูลเก่าก็เริ่มฐานข้อมูลใหม่เปล่าๆ ได้เลย ข้ามขั้นตอนนี้ไป
7. **เปลี่ยนลิงก์ที่แจกให้ทุกคนใช้** จากลิงก์ ngrok/LAN IP ของแล็ปท็อป เป็น IP/ชื่อของเซิร์ฟเวอร์จริงแทน แล้วเลิกใช้วิธี ngrok/รันบนแล็ปท็อปนี้ได้เลย
